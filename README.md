# NAKWON 쇼케이스 라이브 컨트롤

디렉터 태블릿(관리자) → 인터넷(Firebase) → LED 송출 PC(led.html) 로 장면이 실시간 전환되는 사이트입니다.

## 페이지
| 주소 | 용도 |
|---|---|
| `index.html` | 진입 페이지 |
| `admin.html` | 관리자(디렉터 리모컨) — 태블릿/PC |
| `led.html` | LED 송출용 (13920×2160, 창 크기에 자동 맞춤) — 송출 PC에서 F11 전체화면 |

리허설/본방송 분리: 주소 뒤에 `?room=rehearsal` (관리자·LED 모두 같은 room 이어야 연결됩니다. 기본 `main`).
LED 화면 점검: 관리자의 **정렬 가이드** 버튼 → 모서리(노란선, x=6960)와 안전영역 표시.

## 1. Firebase 설정 (약 5분)
1. https://console.firebase.google.com → 프로젝트 추가
2. 빌드 → **Realtime Database** → 데이터베이스 만들기 (위치: 싱가포르 `asia-southeast1` 권장, 테스트 모드)
3. Realtime Database → **규칙** 탭에 아래를 붙여넣고 게시
```
{ "rules": { "rooms": { ".read": true, ".write": true } } }
```
4. 프로젝트 설정(톱니) → 일반 → **내 앱 → 웹 앱(</>) 추가** → 표시되는 `firebaseConfig` 값을 `js/config.js` 에 입력
   (`databaseURL` 은 Realtime Database 화면 상단 주소를 그대로 복사)
5. ⚠ 접근 제한이 없는 규칙입니다. 주소를 비공개로 관리하고, 행사 후 규칙을 `false` 로 바꾸거나 프로젝트를 삭제하세요.

`js/config.js` 가 비어 있으면 **로컬 테스트 모드**로 동작합니다(같은 브라우저 탭끼리만 연결).

## 2. GitHub Pages 배포
1. 이 폴더 전체를 GitHub 저장소에 업로드 (비공개 저장소는 유료 플랜 필요 → 공개 저장소면 주소를 외부에 알리지 마세요)
2. 저장소 Settings → Pages → Branch: `main` / `(root)` → Save
3. 잠시 후 `https://계정명.github.io/저장소명/` 접속 → 관리자: `.../admin.html`, LED: `.../led.html`

## 3. 현장 운영 팁
- LED PC: 브라우저를 **반 해상도(6960×1080) 또는 1/4(3480×540)** 로 띄우고 미디어 프로세서에서 확대하면 부드럽습니다. 풀해상도는 PC 성능을 확인하세요.
- 관리자 상단 표시: `서버 연결됨` / `LED n대 · 반영 완료` 가 모두 초록인지 방송 전 확인하세요.
- **즉시 송출**: 누르는 즉시 LED 반영(디렉터용). **큐 → 송출**: 선택 후 LIVE 버튼으로 송출(PD용).
- 여러 기기에서 관리자를 열어도 버튼 상태는 서버 기준으로 함께 바뀝니다.
- 🔒 잠금: 오터치 방지. 키보드(PC): → / Space 다음, ← 이전, Enter LIVE(큐 모드), B 블랙아웃.
- 인터넷이 끊겨도 LED는 마지막 화면을 유지하고, 복구되면 자동으로 이어집니다.

## 4. 내용 수정
`js/content.js` 한 파일에서 모든 문구·이미지·로드맵 셀·하이라이트 순서를 수정합니다. 이미지는 `assets/` 에 넣고 경로만 바꾸세요.
Noto Sans KR 은 구글 폰트(인터넷 필요), 제목 폰트(Gmarket Sans Bold)는 `fonts/` 에 포함되어 있습니다.

## 5. 화면 구성 규칙
- 섹션 제목 카드 · 로드맵 · 업데이트/추가 예정 소개: **전체 화면(좌우 연결)**. 모서리(x=6960)는 좌/우 묶음 사이 빈 간격에 둡니다.
- 설명 화면: 텍스트는 좌면, 이미지/영상은 **16:9 액자(잘리지 않음)**. 액자 1개는 우면 중앙, 2~3개는 좌면 오른쪽부터 모서리를 피해 나란히 배치됩니다.
- `content.js` 의 `imgs: ['assets/a.webp', 'assets/b.mp4']` 처럼 이미지 또는 영상(mp4/webm, 음소거 반복재생)을 1~3개 넣으면 액자 수가 자동으로 바뀝니다.
- 전체 소개 화면의 좌/우 묶음은 `bars: ['신규','개선']` 과 각 항목의 `group: 0 또는 1` 로 정합니다.
- 화면 전환: 섹션이 바뀔 때는 **철문이 좌우에서 닫혔다 열리고**(`assets/door-L/R.webp`), 같은 섹션 안에서는 안개가 분출됩니다.
- 전체 보기 → 설명은 **전체 화면 팝업**이 올라오고, 다른 항목을 누르면 현재 팝업이 내려간 뒤 다음 팝업이 올라옵니다.
- 타이틀을 뺀 모든 **제목 카드는 1초 뒤 자동으로 다음 화면**으로 넘어갑니다. 시간은 `content.js` 의 `card()` 안 `auto`(ms) 값, 끄려면 `0`. (LED 화면이 직접 넘기므로 LED가 연결돼 있어야 동작합니다.)
- (v4) 제목 → 전체 보기는 **화면이 불타며** 넘어가고, 섹션 전환 철문은 **좌우 / 위에서 내려오는 두 가지**가 번갈아 나옵니다. 안개는 전환용이 아니라 **상시 은은하게 에셋 위에 깔립니다**(관리자의 안개 슬라이더로 농도 조절).
- 타이틀: 연기가 걷히며 시작 → 크랙 로고 → 붉은 화염이 휘날림. 키아트는 우면, 로고는 좌면에 두어 모서리에 걸리지 않게 했습니다.
- 설명 화면의 액자는 이미지/영상 **1~9개**까지 자동 배치(1개: 크게, 3개: 큰 1+작은 2, 4개 이상: 격자).
- (v5) **개발 일정** 섹션(로드맵 앞)과 **Q&A 문의 페이지**(문의 1·2)를 추가했습니다. 일정은 `content.js` 의 `SCHEDULE`(단계·점·칩·아래 띠), 문의는 `QNA.items`(cat/q/detail/label)에서 수정합니다. 문의 항목은 몇 개든 추가할 수 있습니다.
- (v6) 같은 섹션 안 전환(제목 → 전체 보기 등)은 **붉은 디졸브가 좌→우로 훑는** 연출입니다. 전체 보기에서 항목을 누르면 **해당 박스가 화면 가득 커지고**, 다음 항목으로 넘어갈 때는 박스가 제자리로 줄어든 뒤 1초 뒤에 다음 박스가 커집니다.
- 타이틀은 키아트와 로고가 정중앙(모서리)에 놓입니다. 설명 텍스트는 중앙(발표자 자리)을 비우도록 왼쪽으로 이동했습니다.
- (v7) **0번 섹션 = 블랙아웃(대기)**: LED가 검은 화면으로 시작하고, 타이틀을 누르면 재생됩니다. Q&A 구간 전환은 **경보등**, 같은 섹션 안 전환은 **스크린 블렌드 붉은 빛**, 박스 확대 시 **플래시**가 터집니다.
- (v8) 관리자의 안개 분출 / 경보등 / 플래시 버튼은 제거했습니다(화면에서 자동으로 연출됨). 목차는 제목 카드 없이 바로 열리고 1~5번이 차례로 깜빡이며 강조됩니다. 개발 일정은 모서리에서 끊기지 않고 화면 전체에 이어집니다.
